## 🤝 介绍

WakePro 是 AstrBot 的高阶唤醒插件，把「能否唤醒」拆成一套固定顺序的处理流水线。
当前实现中，流水线顺序已经写死，**不再支持通过配置调整阶梯顺序**。

固定顺序如下：

| 顺序 | 配置键名 | 一句话职责 | 说明 |
| --- | --- | --- | --- |
| 阻塞判断 | `block` | 判断当前消息是否应直接拒绝唤醒 | 白名单用户可跳过 |
| 指令屏蔽 | `command` | 拦截被禁用的指令或前缀 LLM 唤醒 | 命中后立即停止，不进入防抖及后续步骤 |
| 消息防抖 | `debounce` | 合并已有窗口内同一用户的连续消息 | 阻塞判断和指令屏蔽通过后执行 |
| 提及唤醒 | `mention` | 处理 @、引用和配置的唤醒词 | 命中后标记唤醒，JEV 跳过判定 |
| 唤醒延长 | `prolong` | 由选中的明确唤醒激活，在时长和次数限制内延续对话 | 激活方式、时长、次数及步骤开关可独立配置 |
| 智能唤醒 | `wake` | 根据相关性、答疑、兴趣等信号判断是否唤醒 | 核心唤醒决策阶段 |
| JEV 唤醒 | `jev` | 结合群聊上下文判断普通消息是否在对机器人说话 | 需要单独配置 JEV 服务 |
| 沉默检测 | `silence` | 唤醒后根据负面信号进入沉默期 | 白名单用户可跳过 |

各步骤按上表顺序执行；禁用或命中管道黑白名单跳过规则的步骤不执行。标记唤醒后仍会继续后续步骤，只有步骤返回中断结果时才结束本次流水线。

## ✨ 说明

### 阻塞判断（block）

流水线的第一步。如果消息里含屏蔽词、在唤醒 CD 内、或是复读 Bot 上一条消息，则直接拒绝唤醒，不进入指令处理和防抖合并。

- 唤醒 CD 默认 0.5 s，每人独立计时，在阻塞判断内部最先检查；窗口内的后续消息也需通过 CD 检查才能合并。
- 屏蔽复读默认开启，可防止“复读机”把 Bot 无限叫起。
- 支持配置屏蔽唤醒的用户 ID，也可通过命令修改并自动保存。
- 用`屏蔽用户 @某人|ID` 将指定用户加入屏蔽唤醒列表。`解除屏蔽 @某人|ID` 将指定用户从屏蔽唤醒列表移除。不带参数时进行查看屏蔽列表。两条指令及 LLM 工具 `llm_set_wake_block` 仅限 AstrBot 管理员使用，且不能屏蔽管理员。
- 两个指令都支持一次艾特多个用户，自动去重并忽略 Bot 自身和全体成员，逐个处理后汇总结果；有有效艾特时优先使用全部艾特目标，否则使用手动输入的单个用户 ID。
- 用户屏蔽遵循 `block` 步骤的启用状态和管道黑白名单跳过规则；命中屏蔽规则的消息不会进入防抖，也不会合并或停止上一条待回复消息。命令权限沿用来源分支，未限制为管理员。

### 指令屏蔽（command）

位于阻塞判断之后、消息防抖之前，按配置拦截内置指令、前缀指令或前缀 LLM 唤醒。命中屏蔽规则后立即停止事件传播和本次流水线，不进入防抖合并、智能唤醒或 JEV 判定；未命中则继续后续步骤。支持三种模式：

- 屏蔽内置指令（如 /llm /tts …）
- 屏蔽前缀指令（如 !help 不再触发插件指令）
- 屏蔽前缀 LLM（如 !聊天 不再唤醒大模型）

唤醒前缀按消息所在会话绑定的 AstrBot 配置文件读取，多配置文件时各会话使用各自的前缀。判断时比对整条消息的文本，开头带引用或艾特 Bot 也能识别；群聊中以艾特他人开头的消息不算前缀消息，与 AstrBot 的规则一致。

屏蔽前缀 LLM 时，可通过“前缀拦截列表”（`block_llm_prefixes`）指定要拦截的前缀。填写后只拦截以列表中前缀开头的非指令消息，不再读取 AstrBot 的唤醒前缀，例如唤醒前缀为 `/` 和 `云云` 时只填写 `/`，即可拦截 `/你好` 而保留 `云云你好`；留空时使用会话的唤醒前缀。已被唤醒的消息会停止事件传播；尚未被唤醒的消息只跳过本插件的后续唤醒判定，不影响其他插件处理。

允许的前缀指令及前缀 LLM 消息会标记唤醒并更新唤醒时间，因此冷却检查在此前完成，避免当前消息被自身触发的冷却误拦截。选中的前缀激活方式仍遵循前面的屏蔽规则。

### 消息防抖（debounce）

阻塞判断和指令屏蔽通过后，如果当前用户已经处在一个已开启的防抖窗口内，就尝试把新消息合并进上一条尚未输出的请求；没有可合并请求时继续提及唤醒。支持配置监听时长、最多合并条数，以及开启窗口的消息类型。

- “参与防抖的消息类型”（`debounce.message_types`）采用带标签的列表多选项：`normal(普通消息)`、`at(艾特Bot消息)`、`reply(引用Bot消息)`、`command(命令消息)`，默认选择前三项。配置类读取时去除括号标签，兼容原来的纯英文值；留空时不开启窗口。消息按命令、艾特 Bot、引用 Bot、普通消息的优先级归类。此配置只控制哪些已唤醒消息能开启监听窗口，窗口内后续消息仍按原规则合并。
- 每条消息在尝试防抖合并前，都会先经过阻塞判断和指令屏蔽。合并后沿用已唤醒状态，并识别合并消息中的明确激活方式；不会额外消耗延长次数，跳过智能唤醒和 JEV 判定，仍受沉默检测约束。
- 检测到 GIF 时不会参与合并。
- 达到最大合并条数后，会立即发起请求，不再继续监听后续消息。

### 提及唤醒（mention）

位于消息防抖之后，处理 @Bot、引用 Bot 消息，以及配置的通用唤醒词和管理员专属唤醒词。命中后标记为唤醒，流水线仍会继续执行智能唤醒等后续步骤；JEV 会跳过已经标记唤醒的消息。

前缀、艾特 Bot、引用 Bot、命中通用或管理员专属唤醒词属于强唤醒，不受“引用别人时不唤醒”和“艾特别人时不唤醒”限制；其中引用唤醒仍需未被禁用。没有强唤醒时，这两项配置会拦截后续唤醒延长、智能唤醒和 JEV 判定。

命令消息跳过本步骤，例如 `#禁言 @某人`；强唤醒和命令仍受前置阻塞判断和指令屏蔽规则约束。命令识别缓存已注册的指令，插件加载或卸载后失效并在下一条消息时重建；按完整命令路径及别名匹配，上下文仅保留首级名称用于内置指令屏蔽。

### 唤醒延长（prolong）

位于提及唤醒之后、智能唤醒之前。选中的明确唤醒方式激活成员的延长资格，其回复开启计时窗口；后续普通消息在窗口内且次数未耗尽时，可以通过延长继续唤醒。时长设为 0 时关闭。

- 步骤启用状态及管道黑白名单跳过规则可独立配置；升级已有配置时，在启用步骤列表中勾选 `prolong(唤醒延长)`，原来对 `wake` 的黑白名单跳过规则也应按需应用到 `prolong`。
- 时长在独立的“唤醒延长”分区中配置（`prolong.seconds`），默认 8 秒，设为 0 时关闭。原配置 `wake.prolong` 已移至此处，升级时请将原时长填入新配置。
- 激活方式（`prolong.activation`）为列表多选项，选项为 `prefix(前缀唤醒)`、`at(艾特唤醒)`、`reply(引用唤醒)` 和 `keyword(唤醒词唤醒)`，默认全选，也可自由组合或留空。配置类读取时去除括号标签并转换为独立的 `WakeType` 枚举，用于匹配唤醒来源。唤醒词包括通用唤醒词和管理员专属唤醒词，引用仍受“禁用引用唤醒”约束。旧字符串配置需改为对应列表，原 `explicit` 对应全选四项。
- 只有选中的激活方式能开启或重置延长资格及次数。智能唤醒、JEV 和未选中的方式不会开启资格，其回复也不会刷新窗口；窗口过期后不能靠这些回复恢复延长。
- 最大延长次数（`prolong.max_count`）默认 0，表示不限。首次激活不计入次数，每次通过延长唤醒消耗一次，防抖合并的连续消息算一次；延长回复重新计时但不重置次数，重新命中激活方式才重置次数。达到次数上限后，仍可继续智能唤醒和 JEV 判断。
- 时间和次数按每个群聊中的用户独立保存。计时从激活或延长唤醒的回复进入发送前处理时开始，没有回复就不刷新窗口；私聊不使用这套延长状态。
- 指令、防抖续发消息和已经唤醒的消息不会消耗延长次数，但命中配置的明确激活方式仍可激活或重置资格。群聊或成员仍在沉默期时不激活、不延长；已有沉默状态的拦截仍由智能唤醒步骤执行。
- 延长命中后，智能唤醒不再重复计算相关性、答疑、无聊、兴趣或概率信号，JEV 也跳过本次判定。

### 智能唤醒（wake）

位于唤醒延长之后、JEV 唤醒之前，先检查已有沉默状态；延长未命中时，再按以下顺序判断普通消息。命中一种信号后即结束本步骤，继续后续步骤。各信号可独立配置：

1. 相关性唤醒（与 Bot 最近 5 条消息做语义相似度）
2. 答疑唤醒（检测到专业问句）
3. 无聊唤醒（检测消息中的无聊信号）
4. 兴趣唤醒（自定义关键词包）
5. 概率兜底（本步骤前面的信号都没命中时，按固定概率尝试唤醒；未命中仍可进入 JEV 判定）

指令、提及唤醒、唤醒延长、智能唤醒或 JEV 唤醒阶段标记唤醒后，符合防抖时长、消息类型、合并条数等条件时会开启监听窗口；后续连续消息先经过阻塞判断和指令屏蔽，再到 `debounce` 步骤尝试合并。

### JEV 唤醒（jev）

JEV 步骤位于普通智能唤醒之后，仅处理没有被前置规则直接唤醒的普通群聊消息。它会把最近的群聊历史和当前候选消息发送到兼容 JEV `systemone` 协议的接口（请求包含 `model`、`state` 和 `questions`），返回的 `noul` 概率达到阈值后才标记为唤醒。

- 在插件配置的 JEV 区域填写 API Key、完整请求地址（通常以 `/v1/systemone` 结尾）和模型名，默认模型为 `jev-latest`。
- 可按需调整唤醒阈值、超时、失败重试次数和发送给 JEV 的历史消息条数。
- 请求失败、响应格式不正确或概率无效时，会跳过本次 JEV 判定，不影响其他唤醒步骤。
- JEV 只负责判断是否应该接话，实际回复仍由 AstrBot 当前配置的主模型生成。

### 沉默检测（silence）

“自我保护”——**仅在唤醒后生效**。
检测到“闭嘴、辱骂、人机”三类负面信号时，Bot 对该用户/群进入一段沉默时间，期间不再响应任何唤醒。
已有沉默状态由后续消息的智能唤醒步骤检查；该步骤被跳过时，不会执行此检查。
沉默时长 = 当前检测分数 × 倍数，阈值越低越容易触发。
